# 个人知识库运维备忘（RAG 实践笔记）

> 样例扩充语料 · 用于演示较长文档的切分与检索引用 · 与评估冻结事实不冲突

## 三条原则（检索演示用）

本笔记明确列出三条原则名称与含义：
1. **可追溯** —— 关键数字与定义必须能在原文定位；
2. **可拒答** —— 笔记未写明的内容不要编造，应说明现有笔记没有依据；
3. **工具分流** —— 算术走计算器，当前时间走时间工具，不要用检索假装算过。

## 为什么要做个人知识库

团队在项目里反复追问同一类问题：某芯片规格、某季度考核口径、某优化器结论。  
把 Markdown / PDF 导入向量库后，Agent 可以按需检索并带 `[n]` 引用，减少「凭记忆回答」造成的口径漂移。

## 入库流水线（对照本仓库）

推荐顺序：加载解析 → 保留 source / heading_path / page 元数据 → 切分 → Embedding → 写入 Chroma → 同步 BM25。  
切分过粗会导致检索噪声大；过细则生成时缺少上下文。当前默认 `chunk_size=512`、`chunk_overlap=64`，Markdown 优先按标题切段。

导入验收检查清单：
- 样例 MD 与 PDF 均能列出 `doc_id`；
- 查询「AlphaCore-7」应命中芯片概览，而不是绩效考核办法；
- 空文本 PDF（纯扫描无文本层）应报错，而不是静默入库。

## 混合检索怎么讲

向量检索擅长语义相近改写；BM25 擅长专有名词与精确词。  
本仓库用 RRF 融合两路召回，再取 Top-K 送给生成或 Agent。Rerank 为可选项：无可用 Key 或接口失败时应 fail-open，回退到融合排序，保证主链路可演示。

答辩口述句式建议：「离线建索引，在线由 Agent 决定是否 retrieve；retrieve 内部是向量 ∪ BM25 → RRF →（可选）Rerank。」

## Agent 与工具边界

已注册工具包括：
- `retrieve_knowledge`：语义检索笔记片段；
- `find_indexed_file`：按文件名查已导入清单；
- `calculator`：安全表达式计算；
- `get_current_time`：本地日期时间星期。

决策不靠 Python `if` 路由，而靠 System Prompt + tool schema + `tool_choice=auto`。  
混合题示例：先检索额定功耗 35W，再用计算器求 3 倍得到 105。

## 引用与拒答模板

生成侧要求正文使用 `[n]`，块头携带 file / chapter / page。  
证据不足、笔记写明「未定义」、或用户要求忽略知识库编造规格时，优先拒答，禁止用外部常识冒充私有笔记。

常见拒答场景备忘：
- 私人缩写 K-max 未定义；
- AlphaCore-7 液冷参数未给出；
- 2025 股权激励等语料中不存在的主题。

## 评估与回归

`tests/eval_questions.json` 覆盖纯检索、纯工具、混合、拒答与对抗题。  
改语料事实句前必须同步改题；仅增补说明段落时，应保证原金标句子仍可被检索到。  
建议回归命令：先 `ingest-sample`，再 `scripts/run_eval.py --mode agent --ids R04,R09,H01,X01`。

## 演示话术（可选）

1. 上传或摄入文档；
2. 问一个需要引用的规格问题；
3. 打开 Trace，指出模型调用了哪个工具；
4. 再问一道拒答题，展示「无法确定」。

本笔记用于丰富知识库文字量，不引入与既有样例冲突的新规格数字。
